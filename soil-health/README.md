# GBoS GEOAI — Soil Health & Land Degradation

This folder contains a GitHub Pages landing page for the GEE project. The original Earth Engine Code Editor script is preserved at:

- [`gee/Gambia_Soil_Health_Land_Degradation.js`](../gee/Gambia_Soil_Health_Land_Degradation.js)

## Important architecture note

GitHub Pages serves static HTML, CSS and JavaScript. It does **not** execute the Code Editor's `ee.*` and `ui.*` APIs. The live analytical application must be published separately as an Earth Engine App. Once published, its URL can be configured in `app-config.js`; the landing page will then expose a launch button and attempt to embed the app.

## Publish the live Earth Engine App

1. Sign in at <https://code.earthengine.google.com/>.
2. Open or import `gee/Gambia_Soil_Health_Land_Degradation.js` and run it in the Code Editor. Do not run it as a normal local JavaScript file: the Code Editor supplies `ee` and `ui`.
3. Test all controls, map layers, region/district/ward/EA selection, legend, statistics, chart and export workflow.
4. Open **Apps** in the Code Editor and create a new app. Choose an appropriate Cloud Project and app ID.
5. Set access to public for this research demonstration, if authorized. Review all code and data first: public app code and referenced asset identifiers may be discoverable.
6. The script references `projects/ee-aishaansu80/assets/GambiaEA_Final1`. Confirm that the app can read this asset and that sharing is authorized under GBoS data-governance requirements. Do not make sensitive data public simply to make the app work.
7. Copy the URL generated by Earth Engine and set it in `app-config.js`:
   ```js
   window.GEE_APP_URL = "https://YOUR-PUBLISHED-APP-URL";
   ```
   Use the exact URL generated by Earth Engine. Do not leave placeholder text.
8. Commit the updated config to GitHub.

Official guide: <https://developers.google.com/earth-engine/guides/apps>

## Enable GitHub Pages

1. Open the repository on GitHub and go to **Settings → Pages**.
2. Under build and deployment, choose **Deploy from a branch**.
3. Select the `main` branch and `/(root)` as the folder, then save.
4. The repository already has a root `index.html` for another dashboard. The soil-health page is intentionally in its own folder so that file is not overwritten. After Pages is enabled, visit:
   `https://silkysingz94-oss.github.io/silkygeo-geoai-builtup-expansion/soil-health/`
   If the repository's Pages URL differs, use the URL shown in Settings → Pages.

## Existing script and data

- Main GEE script: `gee/Gambia_Soil_Health_Land_Degradation.js`
- EA asset referenced by the script: `projects/ee-aishaansu80/assets/GambiaEA_Final1`
- Main inputs include Sentinel-2, Sentinel-1, CHIRPS and SRTM.
- Indicators are remote-sensing screening proxies. They are not direct soil laboratory measurements and require validation before operational use.

## Troubleshooting

- **`ee is not defined`:** the script is running outside the Earth Engine Code Editor/App environment.
- **App loads but map/layers fail:** check the Earth Engine App logs, Cloud Project setup, dataset availability and access permissions for referenced assets.
- **Embedded app is blank:** some app/browser configurations may prevent iframe embedding; use the Launch button to open the published app directly.
- **No live app button yet:** publish the Earth Engine App first and add its generated URL to `app-config.js`.
- **Exports do not work as expected:** verify export support in the published App context and use the Code Editor Tasks workflow where needed.
